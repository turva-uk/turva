# Storybook port plan

This port began with seven frontend components, no Storybook and only the Mantine core packages. Quill Medical's component catalogue supplied the starting point for shared, tested components and their theme, style, story and test helpers. Turva's catalogue provides a common place to review controls and accessibility rather than implementing each new page's presentation separately.

This plan brings across Storybook, shared helpers and general components: typography, icons, buttons, badges, cards, the page header, loading spinners and form fields. Each phase is a pull request in the frontend-only stack on `main`. Personal Claude configuration is not a prerequisite. Quill-only folders, such as `patients`, `appointments` and `messaging`, are not brought across. Phases 9 to 14, added on 17 November 2026, bring the Turva-specific `safety` components across too, with a typed safety API layer over Turva's own routes. Using the components in Turva's existing pages is left for a later plan, which moves each view across one at a time.

## Decisions

### Accessibility gate review, 19 November 2026

The original Jest-based runner is superseded by the supported Storybook Vitest addon. Independent light/dark browser projects replay the stories and interactions without building or serving a static catalogue. The existing contrast fixes remain. A completed story must provide a valid axe report; absent reports, engine errors and malformed results fail the gate instead of being treated as zero violations. Explicit per-story `off`/`todo` exceptions remain visible policies. Unit regressions and real-browser canaries cover successful scans, known contrast failures, engine failure and skipped scans.

The new addon is pinned to 10.6.2, matching the existing Storybook core and including its origin-validation security fixes; the older 10.6.1 addon has published advisories and is not admitted. Its peers explicitly support Vitest 5; `@vitest/browser-playwright` is pinned to the existing Vitest 5.1.0 version. Both are MIT-licensed upstream packages. This replaces the unsupported test runner and its Jest/server/wait tooling, rather than adding a second browser runner. Production dependency resolutions are unchanged. See `./s/frontend test-storybook:ci`, `frontend/vitest.config.ts` and the [local command notes](../s/README.md#sfrontend).

- **npm, not yarn** - Turva's frontend already uses npm with a `package-lock.json`, and `./s/frontend` runs it. Quill's yarn lock is not brought across; versions are taken from its `package.json` and locked afresh.
- **A frontend-only review stack** - rebased onto `main` on 18 November 2026. The former dependency on the personal Claude/tooling stack was removed; it is not an adoption requirement.
- **Foundations first** - the general components are what every later screen is built from, and what the rules name. The Quill-only folders are left behind, and the `safety` components wait for a later plan.
- **The worktree fix rides on this stack** - it is not Storybook work, but it is what stopped this stack's Django suite running, and every later stacked plan built in a worktree hits it too. It changes only the dev set-up, so it is safe on `main` on its own. The branch still takes the stack key, as `feature/storybook-worktree-stacks`.- **Two themes for a while** - the existing pages keep their old theme in `legacyTheme.ts` while the components use the new one, so no page changes until it is moved across on purpose. The one exception is the dark-mode link fix, which the pages take now. The cost is two themes to keep in step, and a switch-over the later plan has to design. It ends when the last view moves and `legacyTheme.ts` is deleted.
- **The server's risk matrix is the only one** - Quill's components look up a risk level in a copy of the matrix in the browser. Turva's rule is that a risk level is derived, never entered, so the ported components ask `assessment-preview/` instead. A slower preview is the cost; two matrices that could disagree is what it avoids (TH-008).
- **Components ahead of the API are marked, not hidden** - Phases 13 and 14 show features Turva has no route for yet. Porting them now keeps Quill's work, and the first line of each story says what is missing. Their types may change when the routes are written.
- **Two form libraries for a while** - porting Quill's form components on `react-hook-form` is faster and safer unattended than rewriting them on `@mantine/form`. Turva carries both until its existing pages move across.

## Markdown parser review, 18 November 2026

`MarkdownView` now delegates parsing to [Marked](https://marked.js.org/), retaining DOMPurify as the final HTML sanitiser. Turva owns only rendering policy: allowed URL schemes, caller-approved asset paths and icons, optional tables and comment visibility. New regression tests protect URLs containing underscores/parentheses, literal code and non-default list numbering. CommonMark list continuations and nested headings replace the former parser's indentation rules. Tests that claimed to cover fenced code now pass real newlines and assert the exact code text.

Marked is a direct runtime dependency, MIT-licensed, with no runtime dependencies and Node 20+ support. Version 17.0.6 matches the `^17.0.1` range of Tiptap's Markdown extension in the later editor PR, so that dependency can share the same package rather than relying on an undeclared transitive import. Marked 18 exists; this compatible-major choice is deliberate, not a claim that 17 is the latest release. Re-evaluate the parser version and performance fixes when reviewing the editor dependency, rather than forcing an unsupported major override through Tiptap. The production dependency audit and regression suite must pass before merge.

Raw HTML remains visible escaped text, not active markup. Comment hiding acts on parsed comment tokens, never fenced/inline code. DOMPurify preserves the ordered-list `start` attribute. This work does not implement document viewing, change evidence on disk or establish clinical approval. The new public-title story uses the darker purple background already selected by the later accessibility PR so its large text meets the contrast requirement.
